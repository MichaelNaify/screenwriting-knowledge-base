# STAGE 3 MASTER IMPLEMENTATION
## Part 2: Diagnostic & Assessment Systems

**Purpose:** Identify creative problems precisely and route to optimal solution methodologies  
**Use When:** Story feels wrong but you can't identify why, or need precision diagnosis  
**Core Principle:** Diagnose root causes, not symptoms

---

## SECTION 1: CHARACTER DIAGNOSTICS

### A. Primary Character Problem: "My Protagonist Feels Flat"

#### DIAGNOSTIC PROTOCOL

**Step 1: Symptom Identification**

Run through these yes/no questions:

□ Do readers/viewers struggle to describe your protagonist?
□ Does protagonist feel interchangeable with

 other characters?
□ Do people say protagonist is "likeable" but can't explain why?
□ Does protagonist observe more than act?
□ Do other characters feel more interesting than protagonist?
□ Does protagonist lack clear internal conflict?
□ Can you remove protagonist without breaking the plot?

**If 3+ boxes checked:** Flat Character confirmed → Continue diagnostic

---

**Step 2: Root Cause Analysis**

Test against these frameworks to identify specific problem:

**TEST A: TRUBY'S DESIRE CHECK**
*Source: Anatomy of a Story (Truby), pp. 58-72*

□ Can you state protagonist's desire in one specific sentence?
□ Does this desire drive most major plot events?
□ Does desire evolve or deepen across the story?
□ Is desire external (visible) AND internal (psychological)?

**If NO to 2+ questions:** Problem = UNCLEAR/WEAK DESIRE

**Immediate Action:**
→ Go to Part 5: Technique Libraries → "Truby's Desire Line Design"
→ Go to Part 7: Problem-Solving → "Passive Protagonist Protocol"

---

**TEST B: McKEE'S DIMENSION CHECK**
*Source: Story (McKee), pp. 376-390*

□ Does protagonist contain contradictions?
□ Can protagonist surprise us while staying consistent?
□ Does protagonist reveal different facets under pressure?
□ Do we see multiple traits, not just one dominant quality?

**If NO to 2+ questions:** Problem = ONE-DIMENSIONAL CHARACTER

**Immediate Action:**
→ Go to Part 5: Technique Libraries → "McKee's Contradiction Reveal"
→ Apply dimension test: List 5 contradictory traits protagonist could have

---

**TEST C: FIELD'S DRAMATIC NEED CHECK**
*Source: Screenplay (Field), pp. 25-31*

□ Does protagonist NEED something urgently by story's end?
□ Is this need specific and measurable?
□ Do we know what protagonist will lose if need isn't met?
□ Does need create immediate pressure?

**If NO to 2+ questions:** Problem = WEAK DRAMATIC NEED

**Immediate Action:**
→ Go to Part 4: Decision Trees → "Structure System Selection"
→ Consider using Field's paradigm for need-driven clarity

---

**TEST D: JOHNSTONE'S STATUS CHECK**
*Source: Impro (Johnstone), pp. 33-74*

□ Does protagonist play clear status (high/low) in scenes?
□ Do status transactions with others feel authentic?
□ Does protagonist's status shift through the story?
□ Can you identify protagonist's default status behavior?

**If NO to 2+ questions:** Problem = BEHAVIORAL INAUTHENTICITY

**Immediate Action:**
→ Go to Part 5: Technique Libraries → "Johnstone's Status Transactions"
→ Map status beats in 3 key scenes

---

**TEST E: SEGER'S RELATIONSHIP CHECK**
*Source: Advanced Screenwriting (Seger), pp. 112-156*

□ Does protagonist have meaningful relationships?
□ Do these relationships drive plot forward?
□ Does each relationship serve different function?
□ Would story work without these relationships?

**If NO to 2+ questions:** Problem = ISOLATION/WEAK RELATIONSHIPS

**Immediate Action:**
→ Go to Part 5: Technique Libraries → "Seger's Character Web"
→ Design relationship dynamics for each major character

---

#### INTEGRATED SOLUTION PATH

**If MULTIPLE tests failed:**

This indicates systemic character architecture problems, not surface issues.

**SOLUTION SEQUENCE:**

**Week 1: Foundation Rebuild**
1. Apply Truby's 22 Building Blocks (Part 5: Techniques)
   - Establish weakness, need, desire, ghost
   - Create character web showing relationships
   - Define moral stance and blind spot

2. Apply McKee's Dimension Test (Part 5: Techniques)
   - Identify 3 contradictory traits
   - Design scenes revealing each contradiction
   - Verify surprises feel earned

**Week 2: Behavioral Integration**
3. Apply Johnstone's Status Work (Part 5: Techniques)
   - Map high/low status in each scene
   - Create status transaction beats
   - Verify behavioral authenticity

4. Apply Seger's Relationship Dynamics (Part 5: Techniques)
   - Define relationship function for each character
   - Create dependency relationships
   - Design relationship-driven plot events

**Week 3: Structural Integration**
5. Apply Field's Dramatic Need (Part 3: Workflows)
   - Ensure need is urgent and specific
   - Connect need to climax
   - Verify need drives 70%+ of protagonist actions

**Week 4: Verification**
6. Run Character Quality Checklist (Part 8: Quality Checklists)
   - Verify all tests now pass
   - Check reader feedback
   - Confirm character drives story

### B. Secondary Character Problem: "My Antagonist Is One-Note"

#### DIAGNOSTIC PROTOCOL

**Step 1: Symptom Check**

□ Antagonist exists only to oppose protagonist?
□ Antagonist has no life outside conflict scenes?
□ Antagonist's motivation is simply "being evil"?
□ You could replace antagonist with natural disaster?
□ Antagonist never surprises you?

**If 3+ boxes checked:** One-Note Antagonist confirmed

---

**Step 2: Root Cause Analysis**

**TEST A: TRUBY'S MORAL FUNCTION**
*Source: Anatomy of a Story (Truby), pp. 147-163*

The antagonist should represent valid alternative solution to story's moral problem.

□ Does antagonist have legitimate worldview?
□ Does antagonist's approach make sense given their background?
□ Could protagonist become antagonist under different circumstances?
□ Does antagonist believe they're the hero of their story?

**If NO to 2+ questions:** Problem = MORAL SIMPLICITY

**Immediate Action:**
→ Apply Truby's Moral Argument (Part 5: Techniques)
→ Write antagonist's moral justification essay
→ Find truth in antagonist's position

---

**TEST B: McKEE'S VALUE ALIGNMENT**
*Source: Story (McKee), pp. 315-334*

Antagonist should pursue same value as protagonist but through opposing methods.

□ Do protagonist and antagonist want same thing?
□ Is their conflict about HOW not WHAT?
□ Does antagonist have moments of sympathy?
□ Can audience understand antagonist's choice?

**If NO to 2+ questions:** Problem = SHALLOW OPPOSITION

**Immediate Action:**
→ Apply McKee's Value Analysis (Part 5: Techniques)
→ Identify shared value (freedom, family, justice)
→ Differentiate methods for pursuing value

---

**SOLUTION PATH:**

1. **Backstory Development** (Truby)
   - Create antagonist's Ghost (formative wound)
   - Define antagonist's Weakness and Need
   - Show how their moral stance developed

2. **Dimensional Complexity** (McKee)
   - Give antagonist contradictions
   - Show antagonist's vulnerability
   - Create moments of unexpected choice

3. **Relationship Function** (Seger)
   - Define antagonist's role beyond opposition
   - Create scenes where antagonist isn't opposing
   - Show antagonist's other relationships

4. **Behavioral Authenticity** (Johnstone)
   - Map antagonist's status behaviors
   - Show status consistency across contexts
   - Reveal status through gesture and tone

**Verification:**
→ Part 8: Quality Checklists → Character Verification
→ Test: Can you pitch story from antagonist's POV?
→ Test: Does antagonist pass Dimension Check?

### C. Ensemble Problem: "My Characters Blur Together"

#### DIAGNOSTIC PROTOCOL

**Symptom Check:**

□ Could you swap dialogue between characters without noticing?
□ Do characters have similar speech patterns?
□ Do characters serve same function in story?
□ Are characters defined by single trait?
□ Do readers confuse character names?

**If 3+ boxes checked:** Character Differentiation Problem

---

**ROOT CAUSE ANALYSIS**

**PROBLEM 1: Lack of Distinct Voice**
*Source: Advanced Screenwriting (Seger), Making a Good Script Great (Seger)*

**TEST:**
- Cover character names in 10 lines of dialogue
- Can you identify speaker by voice alone?

**If NO:** Problem = Homogeneous Dialogue

**Solution:**
→ Part 5: Technique Libraries → "Seger's Voice Differentiation"

**Protocol:**
1. Assign each character:
   - Unique vocabulary level (educated/street/technical)
   - Sentence structure preference (short/complex/fragmented)
   - Speech rhythm (fast/measured/hesitant)
   - Verbal tics or patterns

2. Create voice profiles:
   - Character A: Short sentences, technical terms, no contractions
   - Character B: Long sentences, metaphors, interrupts self
   - Character C: Questions more than statements, apologetic tone

3. Rewrite 3 scenes applying voice profiles strictly

---

**PROBLEM 2: Functional Redundancy**
*Source: Anatomy of a Story (Truby)*

**TEST:**
- List each character's function in the story
- Look for duplicates

**If DUPLICATES FOUND:** Problem = Redundant Character Functions

**Solution:**
→ Apply Truby's Character Web (Part 5: Techniques)

**Protocol:**
1. Assign each character unique function:
   - Main Opponent: Embodies obstacle to desire
   - Ally: Represents one possible path
   - Fake-Ally Opponent: Tests discernment
   - Subplot Character: Mirrors theme differently
   - Relationship Character: Forces self-knowledge

2. Eliminate or merge redundant characters

3. Verify each character advances plot/theme/character uniquely

---

**PROBLEM 3: Status Homogeneity**
*Source: Impro (Johnstone)*

**TEST:**
- Map each character's default status (high/low)
- Check for variety

**If TOO SIMILAR:** Problem = Status Monotony

**Solution:**
→ Apply Johnstone's Status Calibration (Part 5: Techniques)

**Protocol:**
1. Assign each character different default status:
   - High-status: Protagonist, antagonist
   - Mid-status: Sidekick
   - Low-status: Comic relief
   - Variable-status: Trickster

2. Create status hierarchy that shifts by context:
   - At work: Boss high, employee low
   - At home: Dynamics reverse
   - In crisis: Competence determines status

3. Write scenes playing status differences

---

**INTEGRATED SOLUTION:**

**Day 1: Voice Audit**
- Read script aloud
- Mark homogeneous dialogue
- Create voice profiles

**Day 2-3: Voice Rewrite**
- Apply profiles to all dialogue
- Test with blind reading

**Day 4: Function Analysis**
- Map character functions
- Merge or eliminate redundancies

**Day 5: Status Design**
- Assign status levels
- Rewrite 5 scenes with clear status

**Day 6-7: Integration Pass**
- Verify voice + function + status all distinct
- Run Character Differentiation Checklist (Part 8)

## SECTION 2: STRUCTURE DIAGNOSTICS

### A. Primary Structure Problem: "My Story Feels Slow/Draggy"

#### DIAGNOSTIC PROTOCOL

**Step 1: Symptom Identification**

□ Readers say it "takes too long to get going"?
□ Middle section feels longer than it is?
□ You're told to "pick up the pace"?
□ Scenes feel uneventful?
□ Multiple scenes communicate same information?

**If 3+ boxes checked:** Pacing Problem confirmed

---

**Step 2: Root Cause Analysis**

**TEST A: FIELD'S PARADIGM CHECK**
*Source: Screenplay (Field), pp. 7-15, 200-213*

□ Does inciting incident occur by page 10-15?
□ Does first plot point occur by page 25-30?
□ Does midpoint reversal occur around page 60?
□ Does second plot point occur by page 85-90?
□ Does climax begin around page 90-100?

**If NO to ANY:** Problem = STRUCTURAL MIS-TIMING

**Immediate Action:**
→ Part 3: Workflows → Apply Field's Three-Act Template
→ Move plot points to correct pages
→ Cut everything between old and new positions

---

**TEST B: McKEE'S VALUE SHIFT CHECK**
*Source: Story (McKee), pp. 239-258*

□ Does every scene change a value from + to - or vice versa?
□ Can you identify the value change in each scene?
□ Do values reverse or just stay same?
□ Does value change drive next scene?

**If NO to 2+ questions:** Problem = STATIC SCENES

**Immediate Action:**
→ Part 5: Techniques → "McKee's Scene Value Analysis"

**Protocol:**
1. Mark opening value state of scene (trust +3)
2. Mark closing value state of scene (trust -2)
3. If no change: DELETE scene or add turning point
4. Track value through entire script
5. Verify progressive value degradation/improvement

---

**TEST C: TRUBY'S 22-STEP PACING**
*Source: Anatomy of a Story (Truby), pp. 284-326*

□ Do major story beats occur at regular intervals?
□ Does each beat cause the next beat?
□ Are beats spaced 3-7 pages apart?
□ Does story accelerate toward climax?

**If NO to 2+ questions:** Problem = EVENT SPACING

**Immediate Action:**
→ Map your current beat structure
→ Compare to Truby's 22-Step Template (Part 4: Decision Trees)
→ Identify missing beats or clustered beats
→ Redistribute events for rhythm

---

**TEST D: SNYDER'S BEAT SHEET CHECK**
*Source: Save the Cat (Snyder), pp. 69-97*

□ Are all 15 beats present?
□ Do they occur at approximately correct page numbers?
□ Does each beat serve its designated function?
□ Is "Fun and Games" section genuinely entertaining?

**If NO to 2+ questions:** Problem = MISSING/MISPLACED BEATS

**Immediate Action:**
→ Part 4: Decision Trees → "Structure System Selection"
→ If commercial genre: Apply Snyder's Beat Sheet
→ Verify all 15 beats present and functional

---

#### INTEGRATED SOLUTION PATH

**FAST FIX (One Day):**

1. **Macro-Structure Adjustment**
   - Map current plot points (Part 5: Field's Paradigm)
   - Move to correct page ranges
   - Cut everything between moves

2. **Scene Value Verification**
   - Check 10 slowest scenes for value change
   - Delete or revise scenes without change
   - Immediate 10-20% page reduction

**COMPREHENSIVE FIX (One Week):**

**Day 1: Diagnostic Mapping**
- Map all current beats to Truby's 22 Steps
- Map all current beats to Snyder's 15 Beats
- Map all current beats to Field's Paradigm
- Identify gaps and clusters

**Day 2-3: Beat Restructuring**
- Fill missing beats
- Redistribute clustered beats
- Verify causal connections
- Ensure proper spacing

**Day 4-5: Scene-Level Revision**
- Apply McKee's Value Analysis to every scene
- Delete/revise static scenes
- Verify progressive complications

**Day 6: Pacing Optimization**
- Vary scene length for rhythm
- Accelerate toward major turns
- Apply Seger's Transition Logic (Part 5)

**Day 7: Verification**
- Run Structure Integrity Checklist (Part 8)
- Beta reader test for pacing
- Compare to successful comp scripts

---

### B. Secondary Structure Problem: "My Midpoint Doesn't Land"

#### DIAGNOSTIC PROTOCOL

**Symptom Check:**

□ Readers don't notice anything special at midpoint?
□ Story energy doesn't shift at page 60?
□ Midpoint feels like just another scene?
□ Second half feels like more of first half?

**If 2+ boxes checked:** Weak Midpoint confirmed

---

**ROOT CAUSE ANALYSIS**

**PROBLEM: Midpoint Lacks Revelation or Reversal**
*Source: Screenplay (Field), Story (McKee), Anatomy of Story (Truby)*

**FIELD'S MIDPOINT FUNCTION:**
"Reversal that spins story in new direction"

**McKEE'S MIDPOINT FUNCTION:**
"Central reversal that redefines quest"

**TRUBY'S MIDPOINT FUNCTION:**
"First Revelation - false goal exposed"

**All agree:** Midpoint must fundamentally change protagonist's understanding

---

**SOLUTION PATH:**

**Option 1: Revelation Midpoint** (Character-Driven Stories)

Design beats where protagonist discovers:
- Their goal was wrong all along
- Their method has been counterproductive
- Their opponent is actually an ally (or vice versa)
- The real problem is internal not external

**Example:** In *The Matrix*, Neo realizes he can bend the rules (revelation)

**Protocol:**
1. Identify protagonist's false belief (first half)
2. Design event that definitively disproves belief
3. Show protagonist's worldview shatter
4. Redirect goal based on new understanding

**Source:** Part 5: Techniques → "Truby's First Revelation Design"

---

**Option 2: Reversal Midpoint** (Plot-Driven Stories)

Design beats where external situation inverts:
- Hunted becomes hunter
- Weak becomes strong (or vice versa)
- Success turns to failure (or vice versa)
- Stakes dramatically escalate

**Example:** In *Erin Brockovich*, discovery of mass cover-up escalates everything

**Protocol:**
1. Map current power dynamic
2. Design event that inverts dynamic
3. Force protagonist to adapt strategy completely
4. Raise stakes significantly

**Source:** Part 5: Techniques → "Field's Midpoint Reversal"

---

**Option 3: False Victory/Defeat Midpoint** (Hybrid Stories)

Design beats where protagonist appears to win/lose but actually opposite:
- Victory that contains seeds of defeat
- Defeat that forces necessary growth
- Success at wrong goal
- Failure that redirects to right goal

**Example:** In *Groundhog Day*, mastering the day still doesn't end the loop (false victory)

**Protocol:**
1. Give protagonist apparent success/failure
2. Reveal this was wrong metric
3. Force re-evaluation of entire approach
4. Launch into true second half quest

**Source:** Part 9: Case Studies → "Ironic Midpoint Examples"

---

**IMPLEMENTATION:**

**Day 1: Midpoint Diagnosis**
- Identify current page 60 event
- Test: Does it change everything?
- Test: Do readers notice it?
- If NO: Redesign needed

**Day 2: Midpoint Redesign**
- Choose revelation, reversal, or false victory model
- Design 3-5 page sequence
- Ensure it's the biggest moment until climax

**Day 3: Integration**
- Rewrite 5 pages before midpoint (setup)
- Rewrite midpoint sequence
- Rewrite 5 pages after (reaction)

**Day 4: Ripple Effect**
- Verify second half reflects midpoint change
- Adjust plot and character choices post-midpoint
- Ensure new direction sustained

**Day 5: Verification**
- Run Midpoint Checklist (Part 8)
- Beta reader specifically tests midpoint impact
- Verify energy shift is felt

## SECTION 3: DIALOGUE DIAGNOSTICS

### A. Primary Dialogue Problem: "My Dialogue Feels Flat/On-the-Nose"

#### DIAGNOSTIC PROTOCOL

**Step 1: Symptom Check**

□ Characters say exactly what they mean?
□ Dialogue explains plot/feelings directly?
□ Every exchange feels like informational download?
□ Dialogue could be replaced with action description?
□ Readers skim dialogue sections?

**If 3+ boxes checked:** On-the-Nose Dialogue confirmed

---

**Step 2: Root Cause Analysis**

**TEST A: McKEE'S SUBTEXT CHECK**
*Source: Story (McKee), pp. 387-396*

The gap between text and subtext creates dramatic electricity.

□ Does character say one thing but mean another?
□ Is true intention hidden beneath surface words?
□ Do characters pursue goals indirectly through dialogue?
□ Does unspoken create more tension than spoken?

**If NO to 3+ questions:** Problem = NO SUBTEXT

**Immediate Action:**
→ Part 5: Techniques → "McKee's Subtext Design"

**Protocol:**
1. Identify what character REALLY wants in scene
2. Identify what character SAYS they want
3. Ensure these are different
4. Write dialogue that pursues real want indirectly

**Example:**
- Surface: "Would you like coffee?"
- Subtext: "Please don't leave"

---

**TEST B: SEGER'S DIALOGUE LAYERS**
*Source: Advanced Screenwriting (Seger), pp. 67-89*

Effective dialogue operates on multiple levels simultaneously.

**Test each exchange for these layers:**
□ Surface text (literal meaning)
□ Subtext (actual intention)
□ Relationship signal (status/power dynamics)
□ Emotional vector (feeling shift)
□ Thematic echo (connects to story theme)

**If dialogue has < 3 layers:** Problem = SINGLE-LAYER DIALOGUE

**Immediate Action:**
→ Part 5: Techniques → "Seger's Five-Layer Dialogue Filter"

**Protocol:**
1. Take flat dialogue exchange
2. Add layers one at a time:
   - What's the power play?
   - What's the emotional shift?
   - How does it echo theme?
3. Rewrite until 3+ layers present

---

**TEST C: JOHNSTONE'S STATUS TRANSACTIONS**
*Source: Impro (Johnstone), pp. 33-74*

Every exchange is a status negotiation.

□ Does each line raise or lower speaker's status?
□ Do characters play clear status strategies?
□ Can you feel power shifting through dialogue?
□ Does body language match status play?

**If NO to 2+ questions:** Problem = STATUSLESS DIALOGUE

**Immediate Action:**
→ Part 5: Techniques → "Johnstone's Status Through Dialogue"

**Protocol:**
1. Mark each line: ↑ (status raise) or ↓ (status lower)
2. Verify authentic pattern (strong character = varied status moves)
3. Add behavioral beats that reinforce status
4. Test by reading aloud with status awareness

---

**TEST D: VORHAUS'S COMIC DIALOGUE** (For Comedy)
*Source: The Comic Toolbox (Vorhaus)*

Comic dialogue requires precision timing and compressed meaning.

□ Does dialogue have rhythm (setup-build-punch)?
□ Is dialogue compressed (maximum meaning, minimum words)?
□ Does dialogue reveal character game?
□ Are jokes integrated with character/plot?

**If NO to 2+ questions:** Problem = UNFUNNY COMEDY DIALOGUE

**Immediate Action:**
→ Part 5: Techniques → "Vorhaus's Comic Dialogue Patterns"

**Protocol:**
1. Identify comic perspective character holds
2. Ensure dialogue reveals this perspective
3. Apply Rule of Three to exchanges
4. Compress to essential words only

---

#### INTEGRATED SOLUTION PATH

**FAST FIX (2 Hours):**

1. **Subtext Pass** (Choose 3 flattest scenes)
   - Identify what each character REALLY wants
   - Rewrite dialogue to pursue want indirectly
   - Remove all direct statements of emotion/intention

2. **Compression Pass**
   - Cut dialogue by 30%
   - Remove redundancies
   - Apply Seger's "cut on second line you like" rule

---

**COMPREHENSIVE FIX (One Week):**

**Day 1: Diagnostic Audit**
- Mark all on-the-nose dialogue
- Identify scenes with worst dialogue
- Choose 10 scenes for intensive revision

**Day 2-3: Layer Integration**
- Apply Seger's Five-Layer test to each exchange
- Rewrite until 3+ layers present
- Focus on subtext first

**Day 4: Status Calibration**
- Apply Johnstone's status analysis
- Mark all status moves
- Rewrite dialogue with clear status

**Day 5: Compression**
- Cut all dialogue by 25%
- Remove exposition
- Ensure every line does multiple jobs

**Day 6: Voice Verification**
- Check each character's distinct voice
- Apply voice profiles
- Verify differentiation

**Day 7: Polish & Verification**
- Read aloud all revised dialogue
- Run Dialogue Quality Checklist (Part 8)
- Beta reader test for naturalness

### B. Secondary Dialogue Problem: "My Dialogue Sounds Unnatural"

#### DIAGNOSTIC PROTOCOL

**Symptom Check:**

□ Dialogue reads like written language, not spoken?
□ Characters speak in complete sentences?
□ No interruptions, overlaps, or fragments?
□ Every thought completed before next speaker?
□ Sounds formal when it should be casual?

**If 3+ boxes checked:** Unnatural Dialogue confirmed

---

**ROOT CAUSE ANALYSIS**

**PROBLEM: Written Register, Not Spoken Register**

**SOLUTION PATH:**

**Technique 1: Transcription Exercise**
Record real conversations in target setting (office, family, bar).
Transcribe exactly, including:
- Interruptions
- False starts
- Verbal tics
- Incomplete thoughts
- Overlapping speech

Study rhythm and patterns. Apply to your dialogue.

**Source:** Part 6: Teaching Systems → "Dialogue Observation Exercises"

---

**Technique 2: Read-Aloud Test**
- Read all dialogue aloud
- Mark anywhere you stumble
- Mark anywhere rhythm feels wrong
- Revise those spots first

**Protocol:**
1. Record yourself reading
2. Note unnatural moments
3. Rewrite for speakability
4. Repeat until natural

**Source:** Part 5: Techniques → "Seger's Dialogue Rhythm"

---

**Technique 3: Contraction Audit**
- Search script for "cannot", "will not", "do not"
- Replace 90% with "can't", "won't", "don't"
- Exception: Formal characters in formal settings

**Protocol:**
- Find & replace formal constructions
- Verify character voice justifies formality if kept
- When in doubt, contract

---

**Technique 4: Fragment Integration**
- Search for all dialogue that's complete sentences
- Convert 30% to fragments
- Add interruptions and trailing off

**Examples:**
- "I think that we should..." instead of "I think we should go"
- "No. No way. Absolutely—" instead of "I absolutely refuse"

**Source:** Part 5: Techniques → "Natural Speech Patterns"

---

**IMPLEMENTATION:**

**Day 1: Audit**
- Mark all unnatural dialogue
- Identify patterns (too formal, too complete, too neat)

**Day 2: Read-Aloud Pass**
- Record yourself reading script
- Mark every stumble
- Note rhythm problems

**Day 3: Contraction Pass**
- Find & replace formal language
- Add contractions throughout

**Day 4: Fragment Pass**
- Break up complete sentences
- Add interruptions
- Create overlapping speech

**Day 5: Verification**
- Read aloud again
- Compare before/after recordings
- Beta reader test for naturalness

## SECTION 4: THEME DIAGNOSTICS

### A. Primary Theme Problem: "I Don't Know What My Story Is About"

#### DIAGNOSTIC PROTOCOL

**Step 1: Symptom Check**

□ Can't answer "What's your story about?" without plot summary?
□ Different readers identify different themes?
□ Theme feels tacked on, not organic?
□ Can't state theme in one sentence?
□ Remove "theme scenes" and story still works?

**If 3+ boxes checked:** Theme Absence/Confusion confirmed

---

**Step 2: Thematic Discovery Process**

**METHOD A: McKEE'S CONTROLLING IDEA**
*Source: Story (McKee), pp. 115-126*

Formula: **Controlling Idea = Value + Cause**

**Protocol:**
1. Identify value at stake (love, justice, truth, freedom, etc.)
2. Identify its polarity change (+ to - or - to +)
3. Identify cause of final value state
4. State as sentence

**Examples:**
- "Love prevails when we accept others' flaws" (romantic comedy)
- "Justice fails when system protects power" (legal thriller)
- "Freedom emerges through facing truth" (drama)

**If you can't complete this formula:** Your story lacks controlling idea

**Immediate Action:**
→ Part 5: Techniques → "McKee's Controlling Idea Design"

**Protocol:**
1. List final scene's value state
2. Work backward to identify cause
3. Test: Does climax prove this idea?
4. If NO: Redesign climax or revise idea

---

**METHOD B: TRUBY'S MORAL ARGUMENT**
*Source: Anatomy of a Story (Truby), pp. 91-117*

Theme = The moral question your story explores through character choices

**Protocol:**
1. Identify protagonist's moral weakness
2. Identify opponent's contrasting moral position
3. State the moral question they debate
4. Show which position wins through action

**Examples:**
- Moral Question: "Is revenge justified?"
- Protagonist's position: "Yes, when wronged deeply"
- Opponent's position: "No, creates endless cycle"
- Resolution: Shows consequence of each choice

**If you can't identify moral positions:** Theme is absent

**Immediate Action:**
→ Part 5: Techniques → "Truby's Moral Argument Construction"

**Protocol:**
1. Map each major character's moral stance
2. Create explicit moral conflict between them
3. Design climax that tests moral positions
4. Prove one position through consequences

---

**METHOD C: DISCOVERY THROUGH PATTERN ANALYSIS**

If theme is present but hidden, find it through pattern recognition:

**Protocol:**
1. List protagonist's choices at major turning points
2. Identify what they learn from each choice
3. Look for pattern in lessons learned
4. State pattern as thematic principle

**Example:**
- Choice 1: Protagonist lies to protect self → Loses trust
- Choice 2: Protagonist lies to protect other → Creates bigger problem
- Choice 3: Protagonist tells truth despite cost → Finds freedom
- **Pattern:** Story is about truth vs. comfort
- **Theme:** "Uncomfortable truth liberates, comfortable lies imprison"

---

#### INTEGRATED SOLUTION PATH

**DISCOVERY PHASE (Days 1-2):**

**Day 1: Value Mapping**
- List all values present in story (Part 5: McKee's Value System)
- Identify which value is most important
- Track that value's journey through story

**Day 2: Moral Position Mapping**
- Map each character's moral stance (Part 5: Truby's Moral Argument)
- Identify central moral question
- Verify characters embody different answers

---

**INTEGRATION PHASE (Days 3-5):**

**Day 3: Climax Redesign**
- Ensure climax directly tests thematic question
- Protagonist's choice must prove theme
- Remove ambiguity from thematic resolution

**Day 4: Scene Alignment**
- Audit every scene for thematic echo
- Scenes must explore theme from different angles
- Remove/revise scenes that don't connect to theme

**Day 5: Dialogue Integration**
- Add thematic subtext to key exchanges
- Never state theme directly
- Let characters debate theme through their choices

---

**VERIFICATION PHASE (Days 6-7):**

**Day 6: Theme Articulation Test**
- State theme in one sentence
- Test: Does climax prove this sentence?
- Test: Do major choices relate to theme?
- Test: Can readers identify theme without prompting?

**Day 7: Depth Check**
- Verify theme is explored, not preached
- Check that multiple perspectives are shown
- Confirm theme enriches rather than limits

**Verification Tool:** Part 8: Quality Checklists → Theme Integration Checklist

## SECTION 5: METHODOLOGY ROUTING

### When Diagnosis Reveals Multiple Problems

**PRINCIPLE:** Fix structural problems before character problems before dialogue problems

**PRIORITY SEQUENCE:**

**1. STRUCTURE (Week 1)**
Broken structure undermines everything else.
- If structure tests failed: Fix plot points, beats, pacing FIRST
- Use: Part 3: Workflows + Part 5: Structure Techniques

**2. CHARACTER (Week 2)**
Flat characters can't execute good structure.
- If character tests failed: Build character architecture SECOND
- Use: Part 5: Character Techniques + Part 7: Character Protocols

**3. THEME (Week 3)**
Theme must emerge from structure and character.
- If theme tests failed: Integrate theme THIRD
- Use: Part 5: Theme Techniques + McKee/Truby Integration

**4. DIALOGUE (Week 4)**
Dialogue is surface expression of all above.
- If dialogue tests failed: Polish dialogue LAST
- Use: Part 5: Dialogue Techniques

**5. VERIFICATION (Week 5)**
- Run all quality checklists (Part 8)
- Beta reader testing
- Professional feedback
