1.4 Pass 1 — Structure Pass (#structure-pass)

Objective:
Repair macro-architecture and ensure causal coherence between acts and major turns.
Cross-Spine Reference: Field (Three-Act Paradigm), McKee (Value Change per Scene).

Inputs: Scene Energy Report, Act Timeline, Paradigm Grid.
Operations:
	1.	Audit acts for expected page ratios (Setup 25 %, Confrontation 50 %, Resolution 25 %).
	2.	Re-plot major turns to ensure ΔValue moment every ≈ 10 pages.
	3.	Generate “Structure Map v2” and flag variance > 5 %.
	4.	Document genre justifications for structural deviations.

Validation: Sσ ≤ 5 %.
Outputs: Structure Ledger (JSON + visual plot), variance summary.
Governance: Checksum recorded; Scene IDs re-hashed.

⸻

1.5 Pass 2 — Character Pass (#character-pass)

Objective: Unify motivation, flaw, and arc (#character-engineering).
Cross-Spine Reference: Truby (Character Problem), McKee (Desire vs Need).

Inputs: Revised Structure Map, Character Sheets.
Operations:
	1.	Define core need ↔ surface goal relationship.
	2.	Plot decision pressure points per act (#decision-node).
	3.	Rebuild arc = flaw recognition × decision stress.
	4.	Score motivation integrity per scene (≥ 0.8 target).

Validation: Motivation Index ≥ 0.8.
Outputs: Character Arc Graph (ΔMotivation curve).
Governance: Anchor linkage to Stage 2 axioms A5 & A6.

⸻

1.6 Pass 3 — Theme Pass (#theme-pass)

Objective: Align moral argument and premise (#theme-alignment).
Cross-Spine Reference: Truby (Moral Argument), McKee (Controlling Idea).

Inputs: Scene Matrix, Symbol Ledger.
Operations:
	1.	Restate premise as moral equation (e.g., Greed → Generosity).
	2.	Score each subplot for Θ ≥ 0.85.
	3.	Flag contradictions and rewrite beats for alignment.
	4.	Record symbolic reinforcements (#theme-audit).

Validation: Θ ≥ 0.85.
Outputs: Theme Re-Vision Matrix, Premise Ledger.
Governance: Cross-spine checksum Truby ↔ Chitlik 0.97 SCI.

⸻

1.7 Pass 4 — Scene Pass (#scene-pass)

Objective: Guarantee each scene contains emotional movement and narrative function.
Cross-Spine Reference: McKee (Scene Design), Field (Plot Beat Density).

Inputs: Draft vN, Scene Cards.
Operations:
	1.	Run Scene Energy Audit (ΔEmotion ≠ 0).
	2.	Apply #purpose-tag to every scene (setup / development / payoff / pivot).
	3.	Merge or cut flat scenes (E(t)=0).
	4.	Normalize average scene length ≤ 3 pages.

Validation: 95 % scenes pass ΔValue test.
Outputs: Scene Energy Graph + Defect Topology Map.
Governance: Automated E(t) tracker within URS v1.

⸻

1.8 Pass 5 — Dialogue Pass (#dialogue-pass)

Objective: Sharpen voice, subtext, and emotional rhythm.
Cross-Spine Reference: Gordon (Communication Ethic), McKee (Value Change through Speech).

Inputs: Scene v2, Dialogue Transcript.
Operations:
	1.	Apply #subtext-law — text conceals truth.
	2.	Eliminate exposition lines (#economy-principle).
	3.	Calibrate dialogue/action ratio Dρ ≈ 0.6.
	4.	Audit voice consistency per character.

Validation: Dρ ≈ 0.6 ± 0.05.
Outputs: Dialogue Audit Report + Voice Profile Index.
Governance: Checksum hash per dialogue block to prevent drift.

⸻

1.9 Pass 6 — Polish Pass (#polish-pass)

Objective: Refine clarity, rhythm, and readability.
Cross-Spine Reference: Field (Page Economy), Gordon (Workflow Discipline).

Inputs: Locked Dialogue v3.
Operations:
	1.	Proof grammar and format consistency.
	2.	Run readability index (10–12 target).
	3.	Check lexical diversity (0.72–0.78).
	4.	Update change log with pass metrics.

Validation: All indices within range.
Outputs: Draft vN.6 + readability report.
Governance: Checksum and meta-log file.

⸻

1.10 Pass 7 — Delivery Pass (#delivery-pass)

Objective: Finalize submission-ready draft and documentation.
Cross-Spine Reference: Gordon (Professional Cycle Ethic).

	2.	Generate “Rewrite Completion Report.”
	3.	Export to PDF / Fountain with PK header & checksum.
	4.	Submit metadata to Cluster A Ledger.

2.5 Validation Flow (#validation-flow)

Algorithmic Sequence:

For each Scene in Draft:
    Run Scene Energy Audit
    if E(t)=0 → Flag F-02
    Run Structure Variance Test
    if Sσ>5 → Flag F-01
    Compute Θ and Dρ
    if Θ<0.85 → Flag F-03
    if Dρ>0.70 → Flag F-04
Aggregate κ from Pass Logs
    if κ<7 → Flag F-05
Output Defect Topology Graph

Each flagged node receives remediation protocol assignment (#remediation-mapping).

R-04	F-04	Dialogue tightening / subtext recheck	Re-measure Dρ
